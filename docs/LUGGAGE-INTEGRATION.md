# 行李管理整合说明

行李源码已迁入本仓库 `modules/luggage`，与主应用一起构建、一起部署。唯一用户入口为行程工具的 `#luggage`；内部使用同源框架隔离 Vue/Element Plus 与原生页面样式，框架没有独立侧栏、Logo、会议选择或登录，不引用旧的 chatgpt.site 站点。直接打开内部模块文档会显示“请从行程工具进入”。

## 会议开关

在“会议管理 → 会议详情 / 设置 → 行李管理”启用。内部与外部会议均支持，新建与复制会议默认关闭，不自动启用任何生产会议。开启后主导航显示“行李管理”；关闭后保留历史入口。未启用且没有历史的会议不创建模块框架，不加载 Vue/扫码/打印包，不打开行李 IndexedDB，也不启动同步。

开关即时保存，独立于其他会议设置的“保存”按钮。关闭时检查本机当前账号的未领取/未同步记录；服务器还会在事务中检查整个会议的未领取记录，并与写入串行化。无法检查未联网终端尚未上传的记录，必须让所有终端先联网同步。若关闭后收到离线旧记录，服务器拒绝新写入，客户端保留待同步记录，管理员重新开启后可补传。

## 生产数据库升级（必需）

现有数据库为 Supabase/PostgreSQL，不能使用旧独立工程的 MySQL SQL。

在目标 Supabase 项目运行：

`supabase/migrations/2026083101_integrated_luggage.sql`

须先完成已有迁移（特别是系统白名单与 `can_manage_project`）。此迁移只新增行李表、审计表、会议开关字段和四个 RPC，不修改原有行程/审批规则；所有现有会议默认关闭。正式前端在检测不到新字段时禁用开关并显示升级提示，不退化为模拟成功。

- `set_meeting_luggage_enabled`：授权工作人员更改开关。
- `luggage_attendees`：只返回本会议有效名单的 ID、姓名、部门和手机号。
- `sync_luggage_record`：验证会议及人员归属；条码幂等、状态单向推进、拒绝冲突；服务端审计实际登录账号。
- `luggage_ledger_page`：按条码分页，每页最多500条，不受默认1000条接口限制。

所有 RPC 只开放给 authenticated 并校验项目权限；匿名用户不能读写，不能直接写表。RLS 保护读表。会议/参会人硬删除会被行李外键阻止，以保留历史。

胸卡二维码需使用主系统 `attendees.id`（UUID 字符串）。不能把姓名、手机号或 HCP ID 当作唯一胸卡编号。旧独立站的 ATT 示例编号不可直接对应生产名单；如已有真实旧台账，需先做会议和参会编号映射，不能直接改 ID 导入。

## 离线与设备边界

- IndexedDB 数据按登录账号分库、按会议分记录；不会写入 localStorage。
- 会议设置仍由原主应用管理；原主应用自己的设置存储行为未整体改造。
- 首次进入会预下载本会议最少必要名单。寄存/取件先写本地，再异步同步，每次8秒超时，失败保留、30秒重试。
- 首次准备会缓存主应用静态文件、内嵌页面和扫码解码包；关键依赖已改为同站点文件，不依赖 CDN。Supabase、身份、名单、文件接口不进 Cache Storage。
- 本机已在线授权的会议可在12小时内断网重开，只恢复行李页面，不能据此操作其他管理模块。必须看见“页面已缓存”才能离线重开；联网后刷新主页面重新验证登录，再补传。
- 初次登录、初次导入、过期后重新验证均需要网络。离线期间无法即时接收权限撤销或其他终端状态变更。
- 各平板/各账号本地记录独立；离线取件限原终端、原操作账号。导出云端台账供汇总，**不自动复制云端记录到各终端进行重复出库**。
- JSON 备份只含当前会议，跨会议恢复被拒绝；恢复按版本合并，已取不能回到寄存。
- 页面中无独立 JSON 名单导入入口；请通过主系统名单导入后更新现场名单。

## 构建和本地演示

Node 24：

```sh
npm ci --prefix modules/luggage
npm test --prefix modules/luggage
npm run build --prefix modules/luggage
node scripts/build-site.mjs
node scripts/preview-luggage.mjs
```

本地演示地址 `http://127.0.0.1:4173/#settings`，仅预览服务替换为演示模式；`.site-build` 中的生产配置不被改写。发布工作流只上传 `.site-build`，不公开测试、数据库脚本、源码目录或 node_modules。

## 验证与未完成验收

自动验证覆盖2500人导入、多件行李、重复出库、延迟同步确认、CSV转义、备份合并与隔离、存储失败、主界面开关与角色切换；用本地 PostgreSQL 引擎执行迁移并验证匿名/跨会议拒绝、RLS、开关/同步竞态所需的串行锁、重复请求及历史保留。

现场仍须在实际安卓平板和80×120mm打印机上验证摄像头、中文标签、双联裁切、断网重开与补传。浏览器打印对话框不代表物理打印成功。

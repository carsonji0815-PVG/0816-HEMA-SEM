# 礼来会务文件收集系统

用于部门内部集中收集报价、会务确认单、PO 及其他会议文件。

## 启动

需安装 Node.js 20 或更高版本。在本目录运行：

```bash
npm start
```

然后：

- 本机访问：<http://127.0.0.1:8787>
- 部门同事访问：使用启动窗口中显示的“局域网访问”地址。

例如本机局域网 IP 为 `192.168.0.36` 时，同事应访问 `http://192.168.0.36:8787`。不能把 `127.0.0.1` 链接发给其他人，因为该地址只代表访问者自己的电脑。

初始密码统一为 `Lilly@2026`。所有账号首次登录时都会提示修改密码。

## 权限

- 管理员：季亮亮，可查看、新建、上传、下载和删除所有成员空间中的文件。
- 普通成员：占慧、沈祥雨、朱冰焰、陈艳、易敏丽、朱宸玥，只能管理自己的空间。
- 新建项目时通过下拉框选择“外部活动”或“内部活动”。外部活动填写会议编码、活动名称、活动负责人和活动日期；内部活动填写合同编号、活动名称、活动负责人和活动日期。
- 文件夹统一命名为：`会议编码_活动负责人_活动日期`（外部活动）或 `合同编号_活动负责人_活动日期`（内部活动）。
- 成员只能上传报价和未签署会务确认单；管理员负责上传最终采购材料并可管理所有成员文件。
- 场景一（不涉及隐私、知识产权或保密信息）：最终材料为采购订单（PO）＋供应商 PO 确认邮件。
- 场景二（不满足场景一条件）：最终材料为采购订单（PO）＋已签署会务确认单。
- 新建项目时不选择场景；管理员上传文件时通过下拉框选择场景一或场景二，系统据此展示对应材料和完成状态。
- 管理员项目列表会根据所选场景显示 PO、供应商 PO 确认邮件或已签署会务确认单的完成状态。
- 支持文件类型：报价、会务确认单、采购订单（PO）、供应商 PO 确认邮件及其他；单文件最大 50MB。

## 数据与部署

系统使用 SQLite 和磁盘文件存储：

- `data/lilly-meetings.db`：账号、会议、文件索引、签署状态和操作日志。
- `data/files/`：上传的原始报价、确认单和 PO。
- 原有 `index.json`、`users.json` 已自动迁移并作为历史文件保留，不再承担实时写入。

SQLite 已开启 WAL、外键约束和写入等待机制，多人同时操作时由数据库事务保证一致性。

### 自动备份

系统每天凌晨 02:30 自动备份；如果启动时发现超过 20 小时没有备份，会补做一次。默认保留最近 30 天。

手动立即备份：

```bash
npm run backup
```

默认备份位置为 `data/backups/`。正式部署时应把备份放到独立磁盘、NAS 挂载目录或云备份卷：

```bash
BACKUP_DIR=/独立备份目录 BACKUP_RETENTION_DAYS=30 npm start
```

每个备份包含完整 SQLite 数据库、上传文件和 `backup-manifest.json`。恢复前应停止服务，然后使用选定备份中的数据库及 `files/` 替换当前对应内容。

默认允许同一局域网内访问。如只希望本机访问：

```bash
HOST=127.0.0.1 PORT=8787 npm start
```

同事访问时需要满足：电脑连接到同一个公司网络或 VPN、本机防火墙允许 Node 接收入站连接，并且启动系统的电脑不能关机或休眠。正式云端使用时，应配置 HTTPS、私有对象存储或独立备份卷、安全组白名单以及公司允许的访问方式。

### 航班计划核验

系统支持通过“出行日期 + 航班号”取得出发/抵达城市、机场、航站楼和计划起降时间。默认优先使用已配置的 AeroDataBox，未配置时兼容原聚合数据接口。

```bash
FLIGHT_PROVIDER=aerodatabox
AERODATABOX_API_KEY=从API.Market控制台创建的密钥
```

API 密钥只配置在服务器环境变量中，不写入前端代码或 Git 仓库。同一日期、同一航班查询结果默认缓存 12 小时，以减少接口用量。
